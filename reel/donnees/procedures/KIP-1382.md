## Objet

Expose Explicit Configuration Deletions to AlterConfigPolicy Status Current state: Under Discussion Discussion thread:link JIRA:KAFKA-21147 Released: TBD Motivation AlterConfigPolicyimplementations receive anAlterConfigPolicy.RequestMetadatainstance when a configuration change is validated. Itsconfigs()method does not consistently identify explicitDELETEoperations made through the Incremental Alter Configs API. For a topic configuration, deleting an unset override is a no-op and does not generate aConfigRecord. Consequently, the key is absent fromconfigs(). For a broker configuration, Kafka generates a record even when the configuration is unset, so the key is present inconfigs()with anullvalue. A policy therefore cannot reliably determine whether a key was explicitly deleted by inspectingconfigs(). Changingconfigs()so every explicit deletion appears as a key mapped tonullwould resolve this inconsistency, but it would also change the behavior observed by existing policy implementations.
