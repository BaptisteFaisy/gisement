Status Current state: Under discussion Discussion thread:here JIRA:ASF JIRA5aa69414-a9e9-3523-82ec-879b028fb15bKAFKA-20367 1 Motivation Kafka Connect sink tasks currently consume through ordinary consumer groups. Kafka partitions are assigned exclusively to task consumers, which limits useful input parallelism to the partition count. Share groups allow different tasks to acquire different records from the same partition. This is useful for independent, unordered work delivered to databases, services, or other external systems. However, changing the consumer implementation is insufficient. Existing sink connectors may depend on: Exclusive ownership of a source partition. Ordered delivery. Partition lifecycle callbacks. Offset-based recovery. Buffered writes that become durable only duringflush()orpreCommit(). In particular, ordinarySinkTask.put()is allowed to return before destination writes are durable.put returns after buffering -> worker ACCEPTs input -> worker crashes -> buffered destination write is lost Share mode therefore needs an explicit connector-completion contract.
