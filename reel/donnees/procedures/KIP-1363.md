# KIP-1363 - KIP-1363: Add --checkpoint option to kafka-metadata-shell and deprecate --snapshot

> CORPUS REEL - document de conception public de l'ASF, pseudonymise.

**Reference** : KIP-1363
**Version** : 7 du 2026-07-07

## Objet

Status Current state:Under Discussion Discussion thread:here JIRA:KAFKA-20668 Motivation The kafka-metadata-shell tool exposes a option --snapshot to point at the file to read. The flag name is misleading: the metadata snapshot use the .checkpoint suffix, while kafka also has .snapshot files in log directory which are producer snapshots. This leads users to pass the wrong file. This KIP proposesadding a --checkpoint option and deprecating --snapshot (keeping it as an alias for backward compatibility). Public Interfaces This KIP changes the command-line arguments of kafka-metadata-shell.sh. A new option will be added: --checkpoint <path>. The existing options will remain supported as deprecated aliases: --snapshot <path>, -s <path>. Example: bin/kafka-metadata-shell.sh --checkpoint metadata_log_dir/__cluster_metadata-0/00000000000000007228-0000000001.checkpoint Proposed Changes Add --checkpoint as the preferred option for selecting the metadata checkpoint file. Keep --snapshot and -s as deprecated aliases for compatibility. When either deprecated alias is used, the tool will print a deprecation warning recommending --checkpoint.
