Motivation For many releases, Kafka records have been able to include additional information alongside the payload in the form of headers. Compared with other messaging technologies, Kafka has very little standard metadata which describes the records. One obvious kind of metadata which is would be helpful to carry is the “content type” of the records. In a future Kafka with schema support, the schema information would naturally live in the record headers. This KIP proposes using standard headers for carrying this kind of metadata. The presence of this information makes many scenarios easier. For example, a UI for browsing the records on a topic has a much better chance of being able to render the records properly if it can tell what they are. An error topic used to accumulate records which could not be delivered can safely contain many different kinds of records if they have headers enabling them to be deserialized.
