## Objet

Allow Brokers to Disable Compression Types for Client Writes Status Current state:Under Discussion Discussion thread:link JIRA:KAFKA-21178 Released:TBD Please keep the discussion on the mailing list rather than commenting on the wiki. Motivation Kafka supports gzip, Snappy, LZ4, and Zstandard compression for record batches. Brokers must retain support for decompressing every codec that may be present in existing log segments. Removing a codec implementation from Kafka would therefore prevent brokers from reading historical records that use that codec. At the same time, operators may need to prevent new records from being written with a particular compression type. Reasons include a vulnerability in a compression library, a codec implementation becoming unmaintained, native-library compatibility problems, or an operational policy that prohibits a codec. The existingcompression.typebroker and topic configuration does not provide this protection. When it is set to a specific codec, Kafka recompresses incoming records using that codec.
