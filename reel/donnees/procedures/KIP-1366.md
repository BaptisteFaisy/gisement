Motivation Kafka Streams window and session state stores are internally divided into time-based segments, each backed by a separate RocksDB instance. The segment interval controls how wide each segment is in time. Currently, the segment interval for window and session stores is computed automatically asmax(retentionPeriod / 2, 60_000ms)and is not configurable through the public API. This creates two problems: Changing retention requires a full state store restore. Because the segment interval is derived from the retention period, any change to retention also changes the segment boundaries. Since segment boundaries determine the on-disk directory structure and key layout, a retention change invalidates the existing state store data and requires restoring from the changelog topic. This is unnecessarily disruptive — a user who simply wants to keep data longer or shorter should not have to pay the cost of a full restore.
