Motivation System tests are the only tests that run Kafka as real processes, yet contributors run them least: writing one means learning Python and ducktape, and running one locally means setting up ducker nodes. So few people write them, and their failures surface late, in nightly runs. This KIP makes system tests as easy to write and run as integration tests: same language, same JUnit framework,@ClusterTest-style annotations, with containers as the execution mode. That also means less to maintain, and some tests get much faster (the compression test went from ~85s to ~12s). It also lets tests use Kafka the way users do. Command line tools can drive real operations, so gaps between them and the Admin API are caught: while implementing [KIP-1066](https://cwiki.apache.org/confluence/spaces/KAFKA/pages/311627566/KIP-1066+Mechanism+to+cordon+brokers+and+log+directories), a scenario worked through the Admin API but not throughkafka-configs.sh, and only manual testing found it.
