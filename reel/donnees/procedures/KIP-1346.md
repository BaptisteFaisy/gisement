Status Current state:Under Discussion Discussion thread: JIRA:ASF JIRA5aa69414-a9e9-3523-82ec-879b028fb15bKAFKA-20595 Motivation During broker startup,LogManagerparallelizes log loading across partitions using a per-data-directory thread pool controlled bynum.recovery.threads.per.data.dir. However, within each partition,LogLoader.loadSegmentFiles()processes segment files strictly sequentially: eachLogSegmentis opened and sanity-checked one at a time before proceeding to the next segment. This design becomes a startup bottleneck for brokers with a large number of segments per partition. The sequential per-partition loading phase becomes the dominant startup cost. Increasingnum.recovery.threads.per.data.dironly increases the number of partitions loaded concurrently, while segment loading within each partition remains serialized. As a result, broker startup time scales approximately linearly with the maximum segment count of any partition, regardless of the number of available CPU cores or recovery threads.
